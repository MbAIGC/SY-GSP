# 2026-09-04 运行日志时区与「诊断全绿仍提示冲突」修复总结

> 真机反馈: ① 只读诊断全绿仍提示「处理冲突/恢复同步」,运行日志无显示;② 运行日志时间不准。
> 本文件为本轮修复的问题、思路与落实记录。

## 一、问题与根因

### 1. 运行日志时间不准(已确认,确定性 bug)
`src/ui/runtime-logs.js` 存储 `new Date().toISOString()`(UTC),渲染时直接
`replace("T"," ").slice(0,19)` 截取,**未转本地时区**。UTC+8 环境下日志时间恒慢 8 小时。
对照: 历史面板使用 `toLocaleString()`(本地时间),不受影响——问题只在运行日志。

### 2. 「诊断全绿仍提示处理冲突/恢复同步」= 暂停状态无出口 + 日志盲区
- 只读诊断(`_runDiagnosis`)只检查配置/连通/基准,**不呈现暂停状态**;而冲突明细仅
  FILE_CONFLICTS 且有列表时显示,BASE_UNRESOLVED 记录(conflicts=[])在诊断面板完全不可见
  → 出现「全绿却提示冲突」的观感(暂停记录与只读检查项本可独立存在)。
- 陈旧/迁移来的暂停记录若无对应 OPEN 冲突集(历史遗留或集已丢失): 菜单红项 →
  `openSet()` 为 null → 只读诊断;想「重新同步重建冲突集」又被控制器暂停门拦截
  (`sync-controller.js` 手动非决策触发仅 `emit conflict:reopen`)→ **无出口死循环**。
- `controller.dismissConflictPause()` 存在但**全仓库无调用者**,没有 UI 出口。
- 上述被拦截路径(reopen 回退、启动提示、暂停门)几乎**不写运行日志**,且运行日志面板只在
  打开瞬间填充、不实时刷新 → 用户点击同步/处理冲突看不到任何记录(「运行日志无显示」)。

## 二、解决思路与落实

| 文件 | 改动 |
|---|---|
| `src/ui/runtime-logs.js` | ① 导出 `formatLocalTime`(UTC ISO → 本地 `YYYY-MM-DD HH:mm:ss`,非法输入原样返回),render 使用本地时间;② `subscribe` 订阅新增条目;③ 打开日志对话框时订阅实时刷新,销毁(destroy 包装)时退订,不泄漏;④ 空日志显示引导文案(说明哪些动作会产生记录),不再空白 |
| `src/sync/sync-controller.js` | 暂停门拦截留痕: 自动轮次拦截写 `info` 日志,手动触发拦截写 `warn` 日志并提示可用「解除暂停并手动同步一次」 |
| `src/plugin/index.js` | ① `conflict:reopen`/菜单「处理冲突」在无冲突集时写 `logs.warn` 并区分引导;② `_runDiagnosis` 新增置顶「同步状态」检查(暂停中显示 kind/文件数/原因,红叉);③ 新增 `_clearPauseAndSync()`(先 `dismissConflictPause()` 再立即手动同步一次,失败留日志+toast),注入诊断面板 |
| `src/ui/diagnosis-panel.js` | 诊断模式下存在暂停记录时渲染红色状态条与「解除暂停并手动同步一次(请确认冲突已处理)」按钮;点击后清除暂停并立即同步——若冲突真实存在,引擎会重新检测并再次暂停、重建冲突集,安全可逆 |
| `tests/runtime-logs.test.mjs`(新增) | `formatLocalTime` 本地化往返/非法输入、render 时间前缀不再含 UTC、subscribe/退订、容量上限 |
| `tests/controller-state.test.mjs` | 暂停门拦截留痕(自动一次性通知+info、手动 warn+reopen 事件);dismiss 后 manual 同步放行进入引擎装配(哨兵证明) |

不改动: 引擎核心、provider、smoke/verify.mjs;不新增 i18n 键(沿用字面量 fallback 风格)。
