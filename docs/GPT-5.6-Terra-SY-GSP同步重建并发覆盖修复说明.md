# SY-GSP 同步重建并发覆盖修复说明

## 问题

用户已在「同步重建」中明确选择「以远端为准」并输入确认文本，但执行仍使用普通 `manual` 触发类型。远端文件准备下载后，如果思源在落地前生成了同名本地 `.sy` 文件，普通同步的并发保护会中止覆盖并再次进入冲突暂停，导致已确认的重建无法收敛。

## 解决方案

- 新增独立的 `rebuild` 同步触发类型，重建不再冒充普通手动同步。
- 引擎仅在 `rebuild + remote_over_local` 组合下放宽本地落地复查。
- 落地时发现本地已存在同名文件，先写入 `temp/SY-GSP/backup/` 备份，再按更新操作应用远端内容。
- 远端不存在的本地多余文件仍通过既有备份删除流程处理。
- 普通自动同步、手动同步和冲突决策仍保留原有并发保护，不会静默覆盖同步期间新建或修改的文件。
- 重试上下文通过 `originTrigger` 保留 `rebuild` 语义。

## 验证

新增回归测试覆盖以下场景：

- 重建扫描时本地不存在目标文件；
- 下载落地前出现同名本地文件；
- 覆盖前执行备份；
- 文件按更新操作写入，避免 Markdown 模式重复创建文档；
- 普通同步遇到同样的并发变化仍进入冲突暂停。
