# SY-GSP 状态文件单一属主与设备本地状态默认忽略总结（v0.1.10）

## 一、问题与根因

| 现象 | 根因 |
|---|---|
| 4. 手动同步每次都弹只读诊断; 5. 每次都提示首次同步选项 | engine-state.json 被两个组件整文件覆盖: 控制器 `_persistState()` 在每次同步成功后写入仅含冲突暂停键(或空)的载荷,把插件写入的 `firstWriteConfirmed` 抹掉 → 下次手动同步被判定为"首次写入"再次弹向导,形成死循环 |
| 3. 没有问题也提示处理冲突/恢复同步 | 同上: 向导反复出现且残留的方向选择面板被误当作存在基准问题 |
| 1. 未变更文档被再次同步 | 向导循环使每次同步都走"镜像"语义(把被覆盖侧改成本侧一致);思源内核在写盘后会重写部分 .sy(字节变化)→ 镜像把这些文件全部重传。修复后走正常三路合并(基准=上次成功提交),只上传真正变化的文件 |
| 2. petals.json/local.json/bazaar.json 是否必要同步 | 不必要: data/storage 为设备本地运行状态,跨设备同步无意义甚至互相覆盖 |

## 二、修复内容

1. **状态文件单一属主**: 引擎状态由控制器唯一持有并**合并写**(`_engineState` +
   `patchEngineState`);插件 `firstWriteConfirmed` 经控制器写入;冲突解决成功不再
   `saveData(ENGINE_STATE_FILE, {})` 清空整文件;任何一方保存均不清掉另一方。
2. **默认忽略 `data/storage/*`**: petals/local/bazaar 等设备本地状态不再进入同步
   范围(与既有 data/plugins、data/widgets 默认忽略同语义);远端已有副本会在后续
   正常同步中按删除守卫移除;用户自定义忽略配置继续可用。
3. **设置读取统一 `get`**: sync_strategy/ignore_file/sync_range 4 处由 `take`
   改为 `get`(与全部设置读取 API 一致;经仓库地址反复读取验证 take 为非破坏性,
   其余 14 处维持不变)。

## 三、验证

- 单元测试 121/121(新增 3 项: 状态合并写双向不清键、暂停键随清除移除、
  默认忽略命中 storage 三个文件且不影响正常笔记/资源);
- 构建 227 KB;冒烟 12/12;产物核验: 合并写入口、不再整文件清空、默认忽略均已编译。

## 四、升级说明

- 首次运行 v0.1.10 仍可能出现一次首次同步向导(旧状态文件中标记已被此前版本抹掉),
  确认一次后不再出现;
- 若希望恢复同步 data/storage 下某文件,可在设置"忽略文件"中无法反向豁免(默认忽略
  为固定行为),如有需求再评估开放。
