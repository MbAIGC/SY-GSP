# SY-GSP V2 开发计划(GLM)

> 定位:本文档是 V2 的**开发执行计划**,基于 [2060906-ChatGPT-SY-GSP-V2-待规划内容落地计划](./2060906-ChatGPT-SY-GSP-V2-待规划内容落地计划.md) 的设计共识,补充实施前必须定稿的缺口、调整后的里程碑与验收要求。
> 两份文档关系:ChatGPT 文档 = 设计决策与共识;本文档 = 工程化落地计划(顺序、交付物、测试矩阵)。

---

## 一、V2 范围

V2 的四个用户可见目标(与 README「V2 - 待实现功能」一致):

1. GitHub Action 把仓库内 `.sy` 转换为 Markdown 并保持目录结构(在线阅读镜像);
2. 仓库支持目录层级(remoteRoot 多同步空间 + 文档层级清单),不再仅能存储于 `repo/data`;
3. 强制删除后,再次同步不复活(墓碑机制);
4. 插件自动升级(检查 + 提醒先行)。

支撑上述目标的公共基础:**控制面 `.sy-gsp/`**(schemaVersion、remoteRoot 声明、墓碑、后续 Device ACK)。

---

## 二、设计基线(继承自 ChatGPT 方案,不再重复论证)

- 控制面/数据面分离:`.sy-gsp/` 不参与 `data/**` 三方合并;
- **一个 remoteRoot = 一个声明文件**,设备名称仅用于首次声明时生成文件名,声明者不是 owner;
- 本地插件配置是唯一执行真相,远程声明只是发现元数据;
- 并发创建声明走 CAS;不做多数派推荐、不做所有权、V1 不做墓碑 GC 与 Device Registry;
- 数据安全 > 一致性 > 功能扩展 > UI/体验;
- 不推翻现有同步核心(BASE/canonical/manifest/conflict/CAS 全部沿用)。

## 三、对 ChatGPT 方案的 4 项补强(实施前必须定稿)

### 3.1 墓碑失效规则(最关键)

ChatGPT 方案的墓碑结构 `{path, deletedAt, reason}` 缺少**被删内容的信息**。没有它,"强制删除后用户又合法新建同名笔记本"会被永久墓碑误杀——新内容刚创建就被当成"旧文件复活"清掉。

补强:墓碑记录增加被删内容指纹:

```json
{
  "schemaVersion": 1,
  "path": "data/<id>/.siyuan/conf.json",
  "deletedAt": "...",
  "reason": "force-delete",
  "deletedSha": "<被删内容的 git blob sha>"
}
```

判定规则:

- 该路径重新出现且内容 sha **≠** 墓碑 `deletedSha` → 视为用户重新创建,**墓碑自动失效**;
- 内容 sha **=** `deletedSha`(旧文件原样回来)→ 判定为复活,按墓碑清理;
- 整目录注销(removeNotebook)场景:目录下逐文件记录 sha,或记录目录级 hash。

### 3.2 忽略规则的 remoteRoot 适配

现网代码中 `DEFAULT_IGNORES` / `ALWAYS_IGNORES` 全部硬编码 `data/` 前缀(`data/plugins/*`、`data/storage/*`…)。remoteRoot 生效后数据根变为 `<remoteRoot>/data/`,忽略规则必须统一改为 `dataRoot(relative)` 计算前缀,否则切换 remoteRoot 后忽略规则全部失效。ChatGPT 方案第 ④ 步(dataRoot 统一)清单中遗漏此项,实施时必须纳入。

### 3.3 设备名称的非 ASCII 降级策略

声明文件名"中文转拼音"需要引入拼音转换库(体积/依赖)。轻量替代:

- ASCII(字母/数字)字符保留;
- 非 ASCII 字符(中文等)整体降级为 `device-<hash>`(hash = 设备名原始值的短哈希),如 `我的NAS` → `device-a3f2-remoteRoot.json`;
- 不引入拼音库,冲突概率由 hash 区分。

(如坚持拼音方案,需评估依赖体积,再定。)

### 3.4 双向"同时新增"验收纳入 remoteRoot 迁移后矩阵

本轮实测"远端新增 → 拉取 / 本地新增 → 推送"双向正常。remoteRoot 路径映射上线后,双端同时新增的收敛面会变化,**必须把该场景纳入迁移后重测矩阵**(ChatGPT 方案 24 节清单未含)。

## 四、里程碑划分(含顺序调整)

与 ChatGPT 方案 28 节相比的一处顺序调整:**Tombstone 提前到 remoteRoot 迁移之前**——迁移本身触发大量删除/新建,没有墓碑保护时,任一端离线再上线就可能把旧目录数据带回来。墓碑先行,迁移更安全。

### M0 控制面基础

- `.sy-gsp/` 目录约定与 schemaVersion 文件;
- 控制面读写工具(原子写、损坏容忍、schemaVersion 校验);
- `.sy-gsp/**` 加入各端固定忽略与扫描排除。

**交付物**: 控制面模块 + 单元测试。

### M1 墓碑与强制删除(原顺序后置,现提前)

- 墓碑文件(含 `deletedSha`,按 3.1);
- 删除动作写入墓碑(远端删除 / 本地清理 / removeNotebook / 强制删除);
- 规划前墓碑判定:复活识别 + 失效规则;
- 强制删除入口(重建面板列出笔记本,二次确认 + 备份);
- 多端墓碑文件并发写策略(union + 时间戳取最新)。

**交付物**: 墓碑模块 + 引擎接入 + "强制删除"UI + 回归测试(含"删除后同步不复活"、"新建同名失效墓碑"两个专项)。

### M2 remoteRoot 声明 + UI

- 声明文件读写(按 ChatGPT 方案 6/7/9/12/13 节);
- 设备名规范化(按 3.3 降级策略);
- CAS 并发创建;
- UI:自动发现 + 自由选择 + 新 remoteRoot 创建(不做多数派推荐)。

**交付物**: 声明模块 + UI + 测试(覆盖 24 节声明/设备名/UI 清单)。

### M3 remoteRoot 数据路径统一(dataRoot)

- `dataRoot(remoteRoot)` 统一计算函数,替换硬编码 `data/` 前缀;
- 覆盖:扫描范围、忽略规则(按 3.2)、manifest、BASE 存储、provider 路径、资源引用(assets)、备份目录;
- 回归:既有全部收敛性测试在"默认根目录"与"A-Note"两种 remoteRoot 下重跑。

**交付物**: dataRoot 模块重构 + 双 remoteRoot 回归测试。

### M4 remoteRoot 迁移(独立高风险步骤)

- 按 ChatGPT 方案 22 节流程:读旧根 → 确认新根 → 检查目标 → 迁移/初始化 → 验证 → 更新声明 → 更新配置;
- 迁移成功前新 remoteRoot 不生效;目标目录已有不同数据时明确提示,绝不覆盖。

**交付物**: 迁移向导 + 迁移测试(含"目标已有数据"场景)。

### M5 GitHub Action Markdown Mirror

- 读取 `.sy-gsp/*-remoteRoot.json` 动态确定 dataRoot(不写死 paths,push 全量触发,无变化快速退出);
- 多 remoteRoot:**全部 Mirror**(ChatGPT 方案 17 节方案 A);
- `.sy` → Markdown 转换器(第一期:文本/标题/列表/常用块/引用/资源引用;复杂块占位并保留 ID 链接);
- 输出到独立 `mirror` 分支,**绝不回写 `data/**`**;
- 解析失败明确标记,不生成半成品。

**交付物**: Action workflow + 转换器 + fixture 测试(.sy 样本 → 期望 md)。

### M6 插件升级 L1(检查 + 提醒)

- 启动及每日一次调 `releases/latest` 对比版本;
- 顶栏角标 + 菜单"有新版本 vX → vY",点击打开 release 页;
- 不自动安装(L2 实验特性后置,默认关闭)。

**交付物**: 升级检查模块 + 测试(版本对比/限流退避)。

### M7 多端完整验收

- 三端(NAS/安卓/网页端)× 两种 remoteRoot × 双向新增/修改/删除/强制删除矩阵;
- 双向"同时新增"纳入(按 3.4);
- 全部收敛性测试(T1/T2 模式)在最终形态重跑。

## 五、验证要求(全里程碑统一)

- 延续 `tests/convergence.test.mjs` 的 T1(单端收敛)/T2(双端收敛)模式,新增场景必须配对新增测试;

## 六、风险清单

| 风险 | 缓解 |
|---|---|
| `setNotebookConf` 老内核不支持(icon/名称应用) | 已实测可用并带回读验证;失败回退写盘 + 重启提示 |

| 迁移期间旧端上线写回旧目录 | 墓碑先于迁移上线(M1 → M4 顺序调整) |

| 声明文件损坏/多文件声明同一 remoteRoot | 内容优先 + CAS + 不因单设备变化自动删除(ChatGPT 方案 30 节原则) |
