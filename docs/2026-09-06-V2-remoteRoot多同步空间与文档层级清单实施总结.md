## 一、本轮交付了什么

1. **同步数据可存放于远端目录层级**:新增「同步空间」设置 `remote_root`(remoteRoot)。留空 = 默认根目录(远端 `data/**`,与 V1 行为逐字一致);填写如 `A-Note` 后,数据远端位置变为 `A-Note/data/**`,内部保持完整 data 结构。
2. **文档层级清单**:远端仓库根生成 `.sy-gsp/catalog.v1.json`,按「空间 → 笔记本 → 文档」记录 docId/标题/父文档/hpath,供下一轮 GitHub Action Markdown 镜像(M5)还原目录结构,并作为后续二级目录功能的共用基础设施。
3. **控制面 `.sy-gsp/`(M0)**:控制面命名空间、schema 版本文件、损坏容忍解析、稳定序列化;控制面文件在规划层完全隐身,绝不参与数据三方合并。
4. **空间声明(M2)**:`.sy-gsp/<设备名>-remoteRoot.json` 声明文件(一个空间一个声明文件,设备名仅用于首次命名);设置面板提供空间配置、非法值即时校验回退、「检测远程同步空间」只读发现。

**本轮不做**(按既定里程碑后置):M1 墓碑与强制删除、M4 迁移向导、M5 Action、M6 升级检查;二级目录 hpath 物理重排仍属独立评审项。

## 二、关键设计决策与解决思路

### 2.1 边界映射:本地命名空间不变,只在引擎远端边界做映射

- 本地内核相对路径(`data/...`)是全链路唯一内部表示;planner、manifest、冲突快照、内容适配器、工作区扫描**均不感知 remoteRoot**,零改动。
- 读侧:远端树经 `splitRemoteTree` 一次拆分——当前空间数据面(去前缀到本地命名空间)、控制面(`.sy-gsp/**`,远端命名空间单列)、其他(其他空间/仓库杂项,**对规划层不可见**)。
- 写侧:`_pushAtomic` 的 tree 条目与两处 `getFileContent` 统一经 `toRemotePath` 加前缀。
- **核心保证**:切换/启用空间后,其他空间的路径对规划器不可见 → 绝不会把旧根数据误判为"远端全删"(H1 类灾难)或"远端全增";旧数据原地保留。

### 2.2 与实施计划的两处偏差(均为简化,已验证)

| 计划原表述 | 实际落地 | 理由 |
|---|---|---|
| metadata SCHEMA_VERSION 1→2,旧键迁移 | **schema 保持 v1,零迁移**:repoKey 仅在 remoteRoot 非空时追加 `@<空间>` 后缀,空根时与 V1 键格式逐字一致 | 存量基准/冲突集/暂停记录天然兼容,消除计划中列为"最高风险点"的迁移;空根用户升级前后行为完全一致 |
| GLM 3.2:忽略规则改为 dataRoot(relative) 计算前缀 | 忽略规则不改写:远端树先去前缀到本地命名空间、再做忽略匹配 | 匹配始终发生在本地命名空间,硬编码 `data/` 前缀的规则天然继续生效;改动面更小 |

### 2.3 BASE/队列按空间隔离

- repoKey 由 `github:owner/repo:branch` 扩展为 `github:owner/repo:branch@<空间>`(仅非空空间时),三处实现收敛为单一 `composeRepoKey`:metadata-store、sync-queue、插件入口 `_repoKey`,另同步至 sync-context(ctx 携带 remoteRoot,重试重建上下文时透传)与控制器暂停记录键。
- 切换空间 = 新键无基准 = 既有首同步门控/向导接管方向选择,不新增平行的初始化流程。
- remoteRoot 校验(单段、≤64 字符、禁路径分隔符/`.`/`..`/`:`/`@`/控制字符)在引擎 `_checkConfig` 前置拒绝,设置面板输入时即时校验回退。

### 2.4 控制面提交策略

- 声明/层级清单条目并入**首个处理批次**,与数据变更同树原子提交(GPT 蓝本"尽量同一提交");纯下载/删本轮无数据推送时,如有控制面漂移则**独立小提交**并作为本轮 BASE 推进。
- 声明并发语义:条目随引擎原子树提交走引用 CAS;CAS 失败重规划后,下一轮重新发现——若对方已声明同空间则自动放弃自己的声明(实现共识 §13 的 CAS 流程)。
- 层级清单按空间分节:每台设备只重写本端所同步空间的节(节级 last-writer-wins),其他空间的节合并时原样保留;写入前与本端内核数据库重新生成的内容做稳定比较,无变化不提交。远端清单损坏时按"内容优先"以本空间节重建,其余空间设备下一轮自愈。
- 控制面失败**不阻断数据同步**,但必须可见:记入运行日志(`⚠️ 控制面更新失败…下轮重试`),不静默降级。

### 2.5 默认根目录的兼容语义

`remoteRoot=""` 时保持 V1 全树语义(含旧版仓库根布局的残留清理兼容),仅新增一条:控制面 `.sy-gsp/**` 在任何根下都不参与数据规划。这是存量 240 项测试零改动全绿的直接原因。

### 2.6 旧版共存警示层(用户确认后补充)

混用版本的分析结论:默认根目录下数据面互通安全(repoKey/路径一致),但旧版会把新版推送的控制面文件当普通数据(首次误下载到工作区根、清单每次更新都触发旧版冲突暂停;删除会被旧版范围守卫拦住,不演变为数据事故);**新版启用非空空间 + 旧版在跑属于明确禁止组合**——旧版会整份误下载空间数据、新版每次编辑都可能让旧版暂停,且旧版冲突选「保留本地」或「同步重建·以本地为准」(该路径不受范围守卫保护)会从远端批量删除空间数据,进而引发新版端本地清理(可由 git 历史与 temp 备份恢复,属数据事故)。为此新增三层警示:

1. **切换空间必须确认**:`remote_root` 实际发生变化(含切回默认根)时弹自定义确认对话框(不依赖内核 confirm 的取消回调语义),列明旧版共存后果与首同步向导提示;**确认才生效,取消/关闭即回退原值**;纯格式规范化不弹窗。
2. **检测面板风险信号**:「检测远程同步空间」除声明列表外,统计默认根 `data/**` 文件数(判断"可能仍有设备在用默认根/旧版"的唯一可观测间接信号),大于 0 时追加 ⚠️ 风险行;结果随缓存展示。
3. **诊断常驻提醒**:启用非空空间后,诊断面板新增"旧版共存风险"提示行(静态,旧版设备无法远程探测)。

风险知悉的边界:以上均为"提醒 + 签字",不能替代真正的全端升级;插件无法确证对端版本。

## 五、已知限制与未验证事项

1. **真机与端到端未验证**(需真机矩阵):NAS/安卓/网页端三端 × 两种 remoteRoot 的双向同步、多设备声明并发,需在真实 GitHub 仓库执行;建议先在测试仓库验证再用于生产数据。
2. **旧版本客户端约束**:V1 客户端不识别 remoteRoot。启用非空空间前,请先将**所有设备**升级到本版本(设置面板描述已提示);已升级设备对旧根数据完全不可见,不会误删。
3. 现有数据的"搬家"(旧 `data/**` → `<空间>/data/**`)由用户以两步完成:一台设备切空间后向导选"上传本地",其余设备切同空间后选"下载远端";自动迁移向导(M4,含墓碑保护)在下一轮交付。
4. 层级清单位于单一文件 `.sy-gsp/catalog.v1.json`,远端文件损坏时其他空间的节需各自下一轮自愈重建(已按"内容优先"原则处理)。
5. 历史面板浏览的是全仓库提交(含其他空间/控制面文件),属预期行为;非本空间路径的"回滚覆盖本地"已被拦截。
