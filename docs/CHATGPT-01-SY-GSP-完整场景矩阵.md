# SY-GSP 2.0 完整同步场景矩阵

## 1. 判定符号

- **B**：BASE，最近一次确认成功的远端提交
- **L**：LOCAL，本地当前内容
- **R**：REMOTE，远端当前内容
- `=`：内容相同
- `≠`：内容不同
- `∅`：不存在
- LN/RN：本地/远端新增
- LD/RD：本地/远端删除
- LC/RC：本地/远端修改

## 7. Ignore / 同步范围

必须覆盖：新增、修改、删除、取消 ignore、同步范围扩大/缩小、工作空间/data/笔记本范围切换。范围缩小时尤其禁止把范围外文件当作本地删除而删除远端。

## 9. Retry / CAS

必须测试网络失败、timeout、远端变化、push reject、CAS 失败、重试期间本地再次变化，以及 Gitee 部分写入后的恢复。

特别注意：**重试必须携带用户已经做出的 conflict overrides**，不能因为新建上下文而丢失决定。

## 10. 本地并发

同步期间用户修改文件时，必须避免下载/merge/删除覆盖新修改。建议在 snapshot 后保存本地指纹，并在 destructive apply 前重新验证。

## 11. GitHub / Gitee

GitHub 可围绕原子 commit + CAS 测试；Gitee 使用逐文件 Contents API，应额外测试“前 N 个文件已写、后续失败”的 partial write、重试、恢复和最终 BASE。

## 12. 最终收敛

核心验收标准：

> 第一次同步成功后，立即执行第二次同步，必须得到 0 changes。

至少覆盖：
- 本地上传
- 远端下载
- 自动 merge
- 删除
- 首同步
- Markdown
- GitHub 多批次
- Gitee 多文件
- conflict keep_local
- conflict keep_remote
- 网络失败 retry
- CAS 竞争 retry
- partial recovery
