# SY-GSP 阅读镜像部署指南(M5)

把思源 `.sy` 在线转换为 Markdown 阅读目录,直接生成在数据仓库 main 分支的 `repo/<笔记本名>/<标题层级>.md`,GitHub 网页可直接阅读。

## 一、部署(数据仓库侧,约 1 分钟)

在你的**笔记数据仓库**新建 `.github/workflows/render-mirror.yml`:

```yaml
name: SY-GSP 阅读镜像
on:
  push:
  workflow_dispatch:   # 手动触发: Actions 页面「Run workflow」按钮
permissions:
  contents: write
concurrency:
  group: sy-gsp-mirror
  cancel-in-progress: false
jobs:
  mirror:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      # 免维护引用: 转换器变更随插件更新即时生效;如需固定行为可改为版本 tag(如 @v0.2.4)
      - uses: MbAIGC/SY-GSP/.github/actions/sy-gsp-mirror@main
```

## 二、工作方式

1. 每次推送触发;读取仓库内 `.sy-gsp/*-remoteRoot.json` 声明确定全部同步空间(**无声明则跳过**,保护非 SY-GSP 管理的仓库);
2. 逐空间读取 `<空间>/data` 下笔记本(`.siyuan/conf.json` 名称)与 `.sy` 文档,配合 `.sy-gsp/catalog.v1.json` 层级清单还原"笔记本/一级文档/子文档"目录;
3. 转换为 Markdown 写入 `MD-Note/<笔记本名>/<标题层级>.md`(笔记本目录名延续思源 icon emoji 前缀;不存在则创建);资源引用以相对路径指回 `<空间>/data/assets`(GitHub 网页直接渲染);同时在数据仓库根生成 `README.md`(占位文案,手动编辑会被下次运行覆盖);
4. 复杂块(挂件/嵌入查询/数据库/未知类型)生成占位并保留块 ID;单文件解析失败生成占位页并计入 `Mirror-Errors.md`,不阻断整跑;
5. 生成结果与 main 上现有内容逐字节比对,**无变化零提交**(避免推送触发环);有变化由 github-actions[bot] 提交,提交信息带源提交 SHA。

## 三、边界与须知

- 镜像只写 `MD-Note/**`、`Mirror-Index.md`、`Mirror-Errors.md`、`README.md`,**绝不触碰**数据面(`<空间>/data/**`)与控制面(`.sy-gsp/**`);
- 插件(V2 空间隔离)不会把镜像路径当同步数据;**所有参与同步的设备需升级到 v0.2.1 及以上**;
- 笔记本目录与空间容器/`data`/`.sy-gsp` 同名时自动追加 `-Mirror` 后缀;文档重名自动追加 `--短文档ID`;
- 删除/改名文档后,旧镜像文件会残留(第一期不做清理),可手动删除或等后续版本 GC;
- 前提: 插件已生成 `.sy-gsp/catalog.v1.json`(文档树变化后自动更新)。

## 四、实施与验证记录(2026-09-06)

- 实现:`.github/actions/sy-gsp-mirror/`(composite action + Node 转换器,零第三方依赖);映射基于 5 个真实笔记本样本校准(24 种节点类型、PascalCase 键、代码块语言 base64、表格三段结构 NodeTableHead→行→单元格);
- 已知样本外块类型(图片 `TextMarkType:"img"`、嵌入块等)按文档字段名实现并有占位兜底,首次真实仓库运行时如有失真,以样本扩充 fixture 迭代;
- 验证:`npm test` 305/305(新增 5 项:真实样本转换、行内映射、路径防碰撞/保留名、声明发现双位置、清单兜底);端到端冒烟:模拟数据仓库(5 笔记本 7 文档)生成 8 个 md(含索引),第二次运行零提交,确认无推送触发环。
