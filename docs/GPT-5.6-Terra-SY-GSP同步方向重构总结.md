# GPT-5.6-Terra：SY-GSP 同步方向调整总结

## 目标

按照单写入者为主的实际使用场景，调整为：

- 单边变化直接上传或下载；
- 无 BASE 时不再因为双方都有同路径文件就整体暂停；
- 同路径内容不同且没有 BASE 时，优先比较本地文件时间和远端 HEAD 提交时间；
- 时间无法可靠判断时才进入人工冲突；
- 继续保留本地落地前的并发修改保护和远端 CAS 安全检查。

## 主要修改

### 无 BASE 首次同步

`src/sync/sync-engine.js` 不再把“本地与远端都有内容且没有 BASE”直接返回 `BASE_UNRESOLVED`，而是创建空 BASE，交由规划器逐路径判断：

- 仅本地存在：上传；
- 仅远端存在：下载；
- 两端都有同一路径：按内容和时间选择，或进入人工冲突。

插件入口也不再因为无 BASE 阻止自动同步或强制方向同步。

### 同路径新增文件

`src/sync/sync-planner.js` 新增时间决策：

- 本地时间比远端提交时间新超过 2 秒：上传本地；
- 远端提交时间比本地时间新超过 2 秒：下载远端；
- 时间缺失或差异不明显：保留可处理冲突。

内容相同仍然直接视为已收敛。

### `.siyuan` 元数据

仅精确忽略以下笔记本元数据文件：

```text
data/*/.siyuan/conf.json
data/*/.siyuan/sort.json
```

不忽略整个 `.siyuan` 目录，正常 `.sy` 文档仍然参与同步。

### 冲突恢复

保留并发落地安全检查。若远端下载前发现本地在同步期间新建同名文件，仍不覆盖本地，但会进入可恢复的 `FILE_CONFLICTS` 流程，而不是普通失败。

## 测试结果

```text
npm test
141/141 通过

npm run build
构建成功

npm run smoke
12/12 通过
```

新增覆盖：

- 无 BASE 同路径本地较新；
- 无 BASE 同路径远端较新；
- 无法判断时间时进入冲突；
- 首次同步双方各有不同文件时双向收敛；
- `.siyuan/conf.json` 与 `sort.json` 精确忽略，`.sy` 不受影响。

## 设计限制

本地文件 mtime 与 GitHub HEAD 提交时间并非同一时钟，可能受时钟偏差、复制文件和提交批次影响。因此时间差小于等于 2 秒或任一时间不可用时，不自动覆盖，而是保留人工选择。
