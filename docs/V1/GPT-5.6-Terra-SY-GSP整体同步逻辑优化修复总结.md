# GPT-5.6-Terra：SY-GSP 整体同步逻辑优化修复总结

## 修复范围

本轮根据整体代码 Review，优先处理数据安全、首次同步、冲突决策和忽略规则问题。

## 已落实

### 远端状态 404 安全处理

只有远端分支引用本身不存在时，才允许按空仓库处理。若分支已读到、但提交或目录树返回 404，则直接保留错误，不再把远端误判为空树，避免错误删除本地文件。

### 冲突决策传递

控制器同时支持 `Map` 和普通对象，批量保留远端/本地的决策不会再被 `Object.entries(Map)` 转为空集合。无效或空决策会明确报错，不会伪装成已启动同步。

### 目录忽略一致性

带路径的无通配符忽略规则按目录前缀匹配，使本地扫描和远端树过滤保持一致，同时避免 `data/foo` 与 `data/foo-2` 误匹配。

### 本地时间解析

兼容 Unix 秒、Unix 毫秒和 ISO 时间字符串；无效或未来时间不参与“最新版本”判断。

### 诊断可观察性

本地文件诊断增加写入、读取、清理阶段日志，远端 HEAD 检查增加开始和完成日志，可定位卡点。

## Review 结论中仍需后续专门处理的事项

- 推送事务恢复：远端提交成功但本地应用/BASE 持久化失败时，需要持久化提交阶段状态，避免重试重复提交；
- CAS 漂移与本地物化内容的 BASE 语义，需要真实多提交场景进一步验证；
- Markdown canonical SHA 需要端到端验证；
- Gitee 代码当前由平台分支保护/测试覆盖，需单独决定是否恢复；
- 真实思源服务端和真实 GitHub 仓库仍需端到端测试。
