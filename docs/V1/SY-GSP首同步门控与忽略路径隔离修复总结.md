# SY-GSP 首同步门控与忽略路径隔离修复总结（v0.1.11）

## 一、问题与根因

| 现象 | 根因 |
|---|---|
| 只读诊断全绿,手动同步却弹"首次写入前的同步计划预览" | 首同步门控以 `firstWriteConfirmed` 标记为准,该键曾被旧版本整文件覆盖抹掉;而元数据里的已确认基准完好(三路合并已实际执行并暂停在文件冲突上即是证明)——判据用错了对象 |
| 自动同步提示"检测到同步冲突,自动同步已暂停(3 个文件)",但日志只有一行状态、诊断看不到冲突 | `conflictPaused` 只持久化 `conflictCount`,不存路径与原因——冲突不可见,无法定位也无法在面板解决 |
| 预览显示"仅远端 10"(storage 文件),参与规划造成下载/删除/冲突候选 | v0.1.10 默认忽略后这些路径从本地扫描消失,但仍留在基准树/远端树,"本地扫描缺失"被规划器当作删除/下载候选反复进入计划 |

## 二、修复内容

1. **首同步门控以元数据已确认基准为准**(`_hasUnresolvedBase()`): 有基准即走正常
   三路同步,无基准才进入首同步向导;标记键仅作记录不再作为判据。
2. **忽略路径在规划层完全隐身**: 工作区适配器暴露 `ignoreMatcher()`,引擎在规划前
   过滤基准树与远端树(正常与强制两条路径)——被忽略路径不参与下载/删除/冲突/计数,
   远端副本原地保留;诊断的计划预览使用同一匹配器,数字口径一致。
3. **冲突明细可观察**: `conflictPaused` 持久化冲突清单(`{path, reason}`,≤20 条,
   `__base__` 哨兵不入清单);失败日志列出冲突文件与原因;只读诊断新增"当前暂停的
   冲突"区块,有明细才显示。

## 三、验证

- 单元测试 123/123(新增 2 项: 忽略路径不触发下载/删除、冲突明细持久化且
  `__base__` 不入清单;状态合并既有测试保持);
- 构建 229 KB;冒烟 12/12(同步链路检查按新契约同时接受"分类错误"与
  "显式暂停"两种可见结局);
- 产物核验: 门控、引擎过滤、冲突明细、面板区块、预览对齐均已编译。

## 四、升级后操作路径

手动同步不再弹向导,正常三路执行;若仍有冲突,日志与只读诊断会明确列出
冲突文件与原因,在面板选择方向解决后自动同步恢复。
