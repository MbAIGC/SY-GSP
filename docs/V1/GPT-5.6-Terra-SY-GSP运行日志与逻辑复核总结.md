# GPT-5.6-Terra：SY-GSP 运行日志与同步逻辑复核总结

## 一、复核结论

本轮复核确认，之前的运行日志问题主要来自：

- 日志只保存在内存，插件重载后历史丢失；
- 引擎阶段事件没有接入运行日志；
- 日志面板没有持久化恢复和清空能力；
- 诊断异步执行异常时，界面不一定显示失败原因。

同步逻辑方面，已确认并调整为单写入者优先的模型：

- 无 BASE 不再整体阻断；
- 单边文件直接上传或下载；
- 同路径不同内容在无 BASE 时按本地文件时间与远端 HEAD 提交时间选择明显较新的一侧；
- 时间不可用或差异不明显时才保留人工冲突；
- `.sy` 文档继续同步；
- 仅忽略笔记本下 `conf.json` 和 `sort.json` 两类内核元数据；
- 远端 CAS、本地落地前并发检查和冲突快照仍保留。

## 二、本轮修改

### 运行日志

修改 `src/ui/runtime-logs.js`：

- 默认保留上限从 200 条提高到 500 条；
- 增加 `load(plugin)`，从 `runtime-logs.json` 恢复历史；
- 每次新增日志按顺序持久化，避免并发保存互相覆盖；
- 增加清空日志操作；
- 日志订阅使用快照遍历，订阅者异常不会中断其它订阅者；
- 日志面板增加“清空”和“刷新”按钮；
- 诊断面板打开/执行/渲染异常可见，不再表现为无响应；
- 异步诊断返回前如果面板已经关闭，不再向旧 DOM 写入结果。

修改 `src/plugin/index.js`：

- 插件启动时恢复运行日志；
- 监听 `engine:phase`，记录同步操作 ID 和阶段，使过程包含检查、快照、远端读取、规划、合并、提交和推送等阶段。

### 同步逻辑复核与调整

修改 `src/sync/sync-engine.js`、`src/sync/sync-planner.js` 和 `src/plugin/index.js`：

- 删除无 BASE 时“本地与远端都有内容即 BASE_UNRESOLVED”的入口阻断；
- 无 BASE 交由逐路径规划；
- 同路径新增文件使用有效时间决策；
- 远端提交日期来自 GitHub commit API；
- 保留无法判定时的人工冲突，不强制覆盖；
- 首次同步双方拥有不同路径时允许双向收敛。

修改 `src/local/ignore-rules.js`：

```text
data/*/.siyuan/conf.json
data/*/.siyuan/sort.json
```

精确忽略内核元数据，不忽略整个 `.siyuan` 目录。

## 四、限制与注意事项

本地 mtime 与 GitHub 提交时间不是同一时钟。当前只有在时间差超过 2 秒时才自动选边；时间不可用或接近时仍需人工选择，以避免误覆盖。

冒烟测试仍输出一条既有存根提示：

```text
document.contains is not a function
```

这是 smoke DOM 存根没有实现 `document.contains`，不影响 12 项冒烟检查通过，也不是生产思源环境的运行错误。
