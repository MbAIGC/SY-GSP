## 一、Gitee 移除(按用户要求: 删代码+UI+测试,留提示与历史)

- 删除 `src/git/gitee-provider.js`(git 历史保留,后续版本可恢复)。
- 引擎/提交构建器不再按平台分派: `commit-builder.build` 只产出统一批次载荷
  (uploads + deletePaths),`sync-engine` 移除 `_pushPerFile` 与全部 Gitee 分支,只走
  GitHub 原子树提交 + 引用 CAS。
- 插件装配: `_platform()` 恒为 `github`;删除 GiteeProvider import/实例化;
  新增 `_isGiteeConfigured()`(旧版平台标记 `upload_sub_platform===1` 或 gitee.com 地址)
  在同步入口、诊断、预览、历史面板处拦截并提示「Gitee 暂不支持」。
- 设置界面: 删除子平台(平台切换)下拉;平台文件恒加载 github 配置;检测到旧版
  gitee 标记时归一为 0 并落盘,同时给出可见提示(历史 gitee 配置数据文件保留)。
- 测试: 删除 Gitee provider/载荷测试;保留一条「模块不存在」的防复活断言;
  `providers.test.mjs` 增补 GitHub 侧 M6/L1/M1 回归。
- 文档/文案: README、plugin.json、i18n(zh/en)中「支持 Gitee」的描述与占位示例
  已改为 GitHub 或加「Gitee 暂不支持,后续恢复」。

## 二、审查问题修复清单(已落实)

| 编号 | 问题 | 解决思路与落实 |
|---|---|---|
| H1 | 远端 404 折叠为空仓库导致本地被整批判删 | 仅「无确认基准」或「恢复向导强制方向」允许 404→无头;已有基准时在抓取阶段直接进入 BASE_UNRESOLVED 暂停(新增 `FETCHING_REMOTE→CONFLICT_PAUSED` 合法转换)。 |
| H2 | 首次同步取最早提交当基准,远端文件在首提交后被修改 → 假冲突 | 本地为空且远端有内容时,BASE 直接取已观察到的远端 HEAD 树(baseSha=HEAD),所有远端文件相对 BASE unchanged → 全部走下载。 |
| H3 | 推送漂移后 BASE 写成未物化并发头 → 下轮回滚并发修改 | `_pushAtomic` 返回 `{finalSha, baseSha}`;确认漂移(drifted)时 BASE=我方提交,expectedRemoteHead 仍推进到并发头。 |
| H4 | 全部上传超限时批次为空却走成功路径(COMMITTING→SUCCESS 非法转换) | 空批次且存在跳过: 应用本地侧变更并重建清单后抛 `LARGE_FILE`(`SKIPPED_ALL_UPLOADS`,含文件列表),不推进 BASE;部分跳过时已推内容以我方提交推进 BASE 后抛 `SKIPPED_LARGE_FILES`;下一轮已推内容因内容相等(#7)不再冗余上传。 |
| H5 | 暂停状态为单一字段,与仓库无关 | 控制器改为 `Map<repoKey, record>` 并持久化为 `conflictByRepo`;同步门控/徽标/决策按当前 repoKey 读取;旧版单字段自动迁移。 |
| M1 | `_resolveBase` 把任意 getCommit 错误折叠为「无合并基」 | 仅 `httpStatus===404` 才尝试合并基重建;getMergeBase 非 404 上抛(provider 层同步修复),5xx/限流进入重试。 |
| M3 | 重试重建 ctx 丢失用户逐文件决策(overrides) | 重试前暂存 `ctx.overrides`,新 ctx 恢复。 |
| M4 | markdown 模式下 sha/合并/写回混用 raw 与 md 表示 | `.sy` 的规划 sha、合并本地输入、冲突快照统一以「内核导出 md 去 front-matter」为 canonical;导出失败退化为 null → 显式冲突/失败路径,绝不混写。 |
| M5 | apply 前不复查本地是否被并发修改 | 下载(update)/本地删除前按快照 raw sha 复查;快照后变化 → `LOCAL_CHANGED` 可恢复错误中止;下载 create 前检查目标是否新出现。 |
| M6 | getTree 丢弃 truncated 标志 | `truncated:true` → 抛 `TREE_TRUNCATED` 可恢复错误,拒绝用不完整树规划。 |
| L1 | getFileContent sha 返回空串 | 显式 `sha:null`。 |
| L2 | kernel.putFile 只查 resp.ok | 解析响应 JSON 并校验 `code!==0` 抛错。 |
| L3 | 非 2xx arraybuffer 错误体丢失平台消息 | 错误时按 UTF-8 解码提取 message。 |
| L4 | 冲突副本路径用 `path.replace(basename,…)` 可能改错目录 | 按最后一个 `/` 切分,仅改文件名部分。 |
| L5 | setConfirmedCommit 先改内存后持久化,失败不回滚 | 持久化失败回滚内存(setLegacyHint 同步修复)。 |
| #1 | 删除被守卫拦截后 manifest 证据永久丢失 | manifest=「本地当前存在 ∪ (旧清单 ∪ 远端仍存在)且本轮未实际删除」;删除执行成功才移除记录,拦截删除保留证据跨轮重试。 |
| #2 | 强制方向(以本地为准)+ 枚举异常可能误删远端 | 引擎强制路径与规划器 `local_over_remote` 覆盖分支在 `enumErrorOccurred` 时中止(`LOCAL_SCAN_INCOMPLETE`)或转入可见 skippedDeletes。 |
| #3 | skippedDeletes 数组混入计数,且从不通知/入历史 | 结果改为计数,通知与历史记录带「拦删 N / 超大跳过 N」。 |
| #4 | 冲突集只增不减、closeSet 无调用方 | 暂停解决时按暂停 operationId closeSet + 按 repoKey 有界清理(每仓库保留 open 与最近 ≤16 历史集)。 |
| #5 | 自动触发每轮弹设置/向导/诊断对话框 | 自动/启动触发遇到配置缺失、无基准、需选方向时只记录日志(每会话至多一次提示);DiagnosisPanel.show 先销毁旧对话框。 |
| #7 | 双方变更但内容一致仍上传(冗余提交) | 规划器改为 unchanged,由成功轮推进 BASE。 |
