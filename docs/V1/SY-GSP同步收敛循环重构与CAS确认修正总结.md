# SY-GSP 同步收敛循环重构与 CAS 确认修正总结（v0.1.8）

## 一、背景

v0.1.7 后用户实测首同步向导选边仍失败，日志两类错误：

1. `[REMOTE_CHANGED] 远端引用回读不一致,提交未确认`；
2. `[PUSH_REJECTED] HTTP 422: 远端分支已前移,本次提交未写入(force=false)`。

本轮定位原则：**不做逐症状补丁，对写入核心做整体审计后一次交付**。

## 二、审计结论（含对 v0.1.7 文档两处错误表述的更正）

1. **更正：「强制方向从未被实现」是错误结论。** 规划器 `_applyOverride`
   早已实现 `keep_local`/`keep_remote` 逐路径语义（含删除守卫、枚举异常保护）；
   v0.1.6 的向导循环根因只是引擎 `_resolveBase` 在规划器之前拦截。
   v0.1.7 文档中相应表述与「策略 2/3 未消费强制模式」一并更正：
   有基准时策略 2/3 正常走进规划器覆盖语义。
2. **职责边界固化**：引擎 `_runForcedDirection`（一次性镜像，仅向导恢复路径，
   无基准）与规划器 `_applyOverride`（有基准时的策略模式与用户逐文件决策）
   各归其位，两者 plan 产出等价，代码注释已写明分工，避免未来重复造轮子。

## 三、修复内容（写入核心按「远端事实优先的收敛循环」重构）

| # | 位置 | 修复 |
|---|---|---|
| 1 | `git-provider._confirmRef`（新） | 回读确认重构：PATCH/POST 后有界重读（共 3 次，间隔 300ms）应对传播中的旧值；仍未一致时接受「我方提交已进入远端父链」的漂移（并发写手推进），以远端头为新事实并标记 `drifted`；真分叉才报 CONFIRM_FAILED，且改为 `retryable:true`（重新规划在新事实上 CAS 重放，已落库内容经差异计算自然收敛） |
| 2 | `engine._pushAtomic` | 每批成功后推进 `ctx.expectedRemoteHead = finalSha`，修复多批次推送时批 2 必然误判「远端已变化」的机制缺陷；漂移头同样作为下一批期望头与父提交 |
| 3 | `retry-policy.decide` | CAS 竞争（REMOTE_CHANGED/PUSH_REJECTED）绕过「自动重试」开关、始终有界重规划（≤2 次）——CAS 保护下安全收敛是必要恢复路径；开关只治理网络暂态类 |
| 4 | `sync-controller._runWithRetry` | 重规划时保留 `originTrigger`（最初触发者），修复 v0.1.7 门控缺陷：RETRY 重规划会把向导镜像退回普通流程再次被基准门拦截 |
| 5 | `commit-builder` | 删除恒为 1 的死变量 `total`；修正 `github.entries` 的误导注释（引擎推送时自行构建 entries，此处为测试断言的载荷契约数据） |

## 四、验证

- 单元测试 111/111（新增 6 项）：回读传播旧值收敛、并发写手漂移接受、
  真分叉报错且可重试、多批次期望头推进（未修复时批 2 必抛错）、
  CAS 绕过开关且网络类仍受约束、确认失败语义可重试；
- 构建 224 KB；冒烟 12/12；产物核验：`_confirmRef`/`drifted`/`originTrigger`/
  `casRace`/批次期望头推进全部编译进产物，死变量已移除。

## 五、环境排查（非代码）

日志显示 14 秒内远端被推进两次，存在并发写入者。用户已确认旧版 SGSP 插件
禁用并删除；如仍出现 422/回读不一致，需继续排查：第二台设备是否在运行同步
插件、仓库的 Actions/Webhook 是否有自动推送。客户端收敛循环可自愈此类竞争，
但消除竞争源仍是最优解。
