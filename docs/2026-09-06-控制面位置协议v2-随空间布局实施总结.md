# SY-GSP 控制面位置协议 v2 实施总结:控制面随同步空间(`<remoteRoot>/.sy-gsp`)

> 日期:2026-09-06
> 性质:协议变更(schemaVersion 1 → 2)+ 一次存量数据自动迁移
> 验证:npm test 298/298、npm run build 通过、npm run smoke 12/12;推送后 CI 自动发布

---

## 一、决策记录(用户定稿)

v0.2.0 按既有共识把控制面放在**仓库根**(`.sy-gsp/**`);用户提出改为**空间内布局**并确认采纳:

```
repo/
└── SYNote/                        ← <remoteRoot>,用户设置的远程同步空间(名字随配置变)
    ├── .sy-gsp/                   ← 控制面 = <remoteRoot>/.sy-gsp(协议 v2)
    │   ├── schema.json
    │   ├── <设备名>-remoteRoot.json
    │   └── catalog.v1.json
    └── data/                      ← 数据面(内部结构与 V1 完全一致)
        ├── <笔记本ID>/
        └── assets/
```

**采纳理由**:控制面公式统一(`controlDirOf(space)`,空间为空自动退化为仓库根,无特判);**空间自包含**——整个目录拷走/归档/换仓库时元数据跟着走;根目录只剩空间目录,更干净。

**随之确立的语义**:

1. 控制面随空间共存亡:手动删除空间目录 = 放弃该空间的元数据(声明/清单/后续墓碑),其他设备需重新声明;
2. 控制面识别不变式:**路径中任意一段等于 `.sy-gsp` 即控制面**,不参与数据三方合并、对规划层不可见——同时覆盖根级(旧协议/默认根)与空间内两种位置;
3. 声明发现改为扫描任意深度的 `*/.sy-gsp/*-remoteRoot.json`(兼容根级旧位置);未来 GitHub Action(M5) 契约:`.sy-gsp/` 的父目录即空间容器,`data/` 为其数据面;
4. 声明同名避让改为**按文件名**判定(不限层级),避免迁移前后新旧位置同名冲突。

## 二、实现要点

1. `control-plane.js`:`CONTROL_SCHEMA_VERSION = 2`;新增 `controlDirOf(remoteRoot)`;`schema.json` 在新位置以 v2 写入。
2. `remote-root.js`:`isControlPlanePath`(按路径段识别)取代"仅根级前缀"判定;`splitRemoteTree` 因此自动兼容新旧两处控制面,数据面规则不变(`<root>/data/**`)。
3. `declaration-service.js` / `catalog-service.js`:声明与清单位置参数化为 `<space>/.sy-gsp/...`;声明发现正则支持任意深度;清单读取新位置优先、根级旧位置(`LEGACY_CATALOG_PATH`)兜底。
4. `sync-engine.js` `_takeControlPlaneEntries`:新增**旧位置迁移条目**——命名空间下发现根级 `.sy-gsp/**` 时,生成"新位置写入(引用原 blob sha,内容逐字节不变)+ 根级删除",与数据变更同批**原子提交**;`schema.json` 迁移后由协议版本引导覆盖重写为 v2(引导块置于迁移条目之后);CAS 失败由既有重规划机制下轮重试,天然幂等。默认根用户新旧位置相同,零迁移零影响。

## 三、验证

- 迁移专项测试:根级三个旧文件(schema/声明/清单)在首轮同步中迁入 `SYNote 空间/.sy-gsp/`、旧位置全部删除、清单引用同一 blob sha(内容原样)、schema 重写为 `"schemaVersion": 2`、迁移提交确认后推进 BASE、第二轮零提交(不回弹);
- 声明任意深度识别、同名避让按文件名(旧位置占用亦触发)、双位置清单读取兜底;
- 全量 298/298(存量 240 语义不受影响)+ build + smoke 12/12。

## 四、已知风险与升级要求

1. **多端混用版本**:v0.2.0 旧版仍向仓库根写控制面,与 v0.2.1 的迁移会形成"搬走—写回"小循环(仅控制面小提交,数据无损)。**多端混用前请先将所有设备升级到 v0.2.1 及以上**(与 remoteRoot 的升级要求合并执行)。
2. 迁移与推送复用同一 CAS 机制,竞争时下轮重试;迁移期间读取双位置兜底,不出现读空窗口。
3. 控制面随空间共存亡的语义(第一节第 1 条)对用户是知情约定;未来"删除空间"如做成插件功能,需显式二次确认。
