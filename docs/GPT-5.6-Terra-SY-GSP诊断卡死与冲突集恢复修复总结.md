# GPT-5.6-Terra：SY-GSP 诊断卡死与冲突集恢复修复总结

## 已确认问题

运行日志显示：

```text
状态: CONFLICT_PAUSED (冲突暂停: FILE_CONFLICTS)
手动同步被暂停门拦截
冲突处理入口: 暂停记录存在但冲突集缺失
```

这表明引擎暂停记录仍然存在，但持久化冲突明细已经丢失，因此菜单无法打开批量保留本地或远端的操作界面。

只读诊断方面，原流程没有超时。只要思源内核文件接口或 GitHub 请求一直不返回，界面就会永久显示加载动画。

## 修复内容

### 诊断超时

修改 `src/ui/diagnosis-panel.js`：

- 只读诊断增加 20 秒超时；
- 首次同步计划预览增加 20 秒超时；
- 面板增加 25 秒看门狗；
- 超时显示明确错误，不再永久转圈；
- 面板关闭后，异步结果不会写入旧面板；
- 超时计时器在正常完成后清理。

修改 `src/plugin/index.js`：

- 记录只读诊断开始和完成日志；
- Gitee 快速返回路径也记录完成状态。

### 缺失冲突集恢复

修改 `src/plugin/index.js`：

- 当 `FILE_CONFLICTS` 暂停记录存在但冲突集缺失时，从暂停记录中的路径、原因和 SHA 信息重建冲突集；
- 等待冲突集持久化完成后再打开冲突对话框；
- `sync:conflict` 和 `conflict:reopen` 两条入口统一使用恢复逻辑；
- 重建成功或失败均写入运行日志。

### 日志时间

运行日志界面时间改为：

```text
MM-DD HH:mm:ss
```

内部仍保存完整 ISO 时间，不影响排序和持久化。

## 验证结果

```text
构建成功，index.js 约 247 KB

npm run smoke

通过
```

冒烟测试仍有既有测试存根提示：`document.contains is not a function`，不影响 12 项检查通过。

## 限制

如果历史暂停记录本身没有保存冲突路径，则无法恢复具体冲突文件；此时诊断面板会在超时后给出可见结果，仍需通过解除暂停并手动同步重新生成冲突集。
